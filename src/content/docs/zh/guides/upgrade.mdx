OpenMausBot 几乎每天都发新版本（按 npm 上的发布时间，2026 年 11 月 2 日到 11 日（UTC）发了 0.1.138 到 0.1.153 共 16 个），但不必每版都升。新版本修了你遇到的问题，或者加了你想要的功能，再升级就行。

## 前提条件

- 一台 OpenMausBot 服务器，这台电脑能用 `ssh myserver` 登录（见[如何用家里的小主机 24 小时跑 OpenMausBot](/zh/guides/home-server/)），并且按那篇的方式用 npm 安装、固定了版本号。

下文的 `myserver` 是服务器的 SSH 别名，`<…>` 是要换成你自己的值。

## 先做决定

- 固定版本号。安装时写明具体版本，不要用 latest，这样想回到旧版本也很简单。
- 先备份。Bot、会话、记忆默认都在 `~/.openmausbot` 里（服务用 `--data-dir` 或 `OMB_DATA_DIR` 指定了别的目录，就以那个为准）。这个目录可能很大，先看大小再决定怎么备份；里面的 `tools` 目录放的是 OpenMausBot 下载的引擎和浏览器；想排除它省空间，先看看里面有没有别的东西，恢复时如果没保留原来的 `tools`，就要重新安装需要的工具。也可以在高级模式的 **设置 → 备份 → 导出完整备份** 里导出一份带密码的备份（密码至少 12 位），已保存的账户凭据和连接、其他 AI 应用的登录、远程桌面磁盘不在里面；导出前等手头的 Bot、审批、登录和电脑操作结束，停掉会写工作区文件的外部编辑器和托管桌面；这种备份要在同一页的 **导入备份** 里按页面提示恢复，它会替换当前的工作区数据，不是合并。各引擎的登录默认在它们自己的位置（比如 `~/.codex`、`~/.claude`、`~/.claude.json`），不在这个目录里，要备份的话得另外备；改过它们的主目录或数据目录的，以实际位置为准。

## 交给 AI Agent

```text title="提示词"
检查我的 OpenMausBot 服务器（ssh 别名 "myserver"）要不要升级，我同意的话就安全地升级。

1. 列出已安装的版本和 npm 上的最新版本，总结这两个版本之间的 GitHub release notes，
   重点标出跟我在用的引擎和功能有关的内容（不确定我用什么就问我）。
2. 等我同意。先查服务实际用的数据目录（默认 ~/.openmausbot），告诉我它有多大、磁盘还剩多少，然后停掉 openmausbot 服务，
   以及还在往这个目录写文件的引擎进程和托管桌面（数据库要在停写时复制），
   再备份它，排除 tools 目录（排除前先列出里面有什么给我确认）。备份里有凭据和配对会话：先 umask 077，新建一个只有我能读的空目录，归档写进去，不要覆盖任何已有的备份。
   再看看 ~/.codex、~/.claude、~/.claude.json、~/.agent-browser 和不在这个目录里的工作区有哪些存在，问我要不要另外备份。
3. 确认备份成功后，以运行 openmausbot 服务的那个账号运行 `npm install --global --prefix "$HOME/.local" openmausbot@<新版本>`，确认安装成功再启动服务，
   等到服务 active、/api/health 有响应。
4. 验证：`openmausbot doctor`、Bot 数量没变、已配对的会话都还在、我主力引擎的模型列表能加载、
   远程访问地址仍然返回 200。
5. 把回滚到旧版本的准确命令给我。
```

## 验证

升级后，把已经打开的浏览器和手机页面刷新一下，加载新版本，再给任意一个 Bot 发一句话，能正常回复就行。

## 回滚

出问题的话，把这段发给你的 AI Agent：

```text title="提示词"
把我的 OpenMausBot 服务器（ssh 别名 "myserver"）回滚到 <旧版本>：先停掉 openmausbot 服务，以及还在往数据目录写文件的引擎进程和托管桌面，以运行服务的那个账号用 npm 把这个版本重新装到它的 ~/.local，确认安装成功后，用升级前打的那个归档完整替换数据目录（升级前确认的那个）：除了 tools 目录，把现在的内容先移到一旁，再解压归档，放回原路径，文件归属不变，再启动服务，确认服务 active 后告诉我结果。
```

回滚时一起恢复升级前的数据，旧版本读到的就是它自己写下的数据。代价是升级之后新产生的对话和改动会丢。归档里没有 `tools` 目录，所以要保留现有的那份；如果已经没了，就重新安装这些工具。

## 升级前先看 release notes

比如 0.1.145 修了一个问题：OpenCode 新出的模型在列表里不显示，点刷新也没用（当时 App 安装的 OpenCode 2.2.5 不认旧的刷新命令）。升级以后，服务运行时会定期检查，上次读取超过三小时就重新读一次模型列表；刷新也改成了 OpenCode 2 能用的方式。正被某个问题卡住时，先查一下新版本是不是已经修了。
